## 2. Критерії виходу

Тестування за цим планом вважається завершеним, коли одночасно виконано:

1. **CI зелений.** Обов'язкова перевірка `build` (workflow `CI`, self-hosted Windows runner) проходить на PR у `main`: зелені всі рядки плану, крім явно помічених «поза воротами CI цієї ітерації» (рядок 11 — потребує PostgreSQL, якої в конвеєрі ще немає).
2. **Покриття.** `pytest --cov=api --cov-branch --cov-fail-under=N` не падає, артефакт `coverage.xml` вивантажено. Поточний поріг `N = 50` — тимчасовий. Критерій виходу: `N ≥ 85` (фактичні 94% мінус 9 п.п. запасу на різницю платформ CI та локального прогону) **і** покриття доменного модуля бронювання ≥ **70%** (MAINT-001). Значення 85 узгоджує команда в PR, що піднімає поріг.
3. **Негативні сценарії.** Кожен із трьох модулів має щонайменше один зелений негативний тест-кейс плану.
4. **Простежуваність.** 0 рядків таблиці без ID вимоги з `rtm.md`; кожен ризик R1–R5 має щонайменше один рядок; усі тест-кейси з обсягу §1, не включені в цю ітерацію, перелічені в §9 — а не пропущені мовчки.
5. **Дефекти.** 0 відкритих issue з міткою `bug` і пріоритетом critical/blocking на гілці `main`.
6. **Супутні перевірки CI.** `scripts/check_requirements.py` і drift-перевірка OpenAPI зелені.

## 3. Ризики — з них починається таблиця

| ID | Ризик | Імовірність × вартість | З чого починаємо |
|---|---|---|---|

Окрема небезпека — **хибна впевненість**: наявний тест ганяє 40 паралельних запитів через `ThreadPoolExecutor`, але проти in-memory сховища з GIL, а не проти PostgreSQL із реальними транзакціями. | **R2** | **Часові пояси й перехід на зимовий час.** Припущення A-007, горизонт A-001 і граничний час скасування рахуються в UTC, показуються в Europe/Kyiv. Перехід 25.10.2026 потрапляє в горизонт пошуку. Зсув на годину — тихий дефект, що не падає в тестах із «круглим» часом | середня × висока | рядки 4, 5 |

## 5. Поточний стан прогону

Локальний прогін 2026-10-19 на клоні `cb95d33`:

```
96 passed · покриття (branch) TOTAL 94%
src/api/stubs/booking_service.py  98%
src/api/stubs/slot_service.py    100%
src/api/stubs/resource_service.py 95%
```

**Застереження до цих цифр.** Прогін виконано на Linux / Python 3.13; CI працює на self-hosted Windows runner із Python 3.12. Числа вважаються підтвердженими лише після зеленої перевірки `build` і завантаженого артефакту `coverage.xml`. До того моменту це орієнтир, а не доказ MAINT-001.

**Наслідок для порога.** Чинний `--cov-fail-under=50` нижчий за фактичний рівень удвічі: він пропустить втрату половини покриття без жодного сигналу. Пропозиція — підняти поріг окремим PR після підтвердження в CI.

**Виконано.** Поріг піднято до 90% сукупного показника для `api` і `unislot` у PR-08
(Лаб6); CI застосовує його через `scripts/run_lab06.py`. Позитивну й негативну перевірки
порога збережено в `docs/testing/lab06/evidence/gate-positive.txt` і `gate-negative.txt`.

## 7. Припущення

- Час у тестах заморожено фікстурою `frozen_world` (`tests/conftest.py`, `NOW = 2026-10-19T09:00Z`). Правила A-001, A-003, A-006 перевіряються детерміновано; горизонт свідомо перетинає перехід на зимовий час 25.10 (R2).
- Автентифікація в stub-режимі — демонстраційні токени (`UNISLOT_DEMO_AUTH`). Тести RBAC перевіряють правила авторизації, а не стійкість механізму видачі токенів.
- Кожен рядок таблиці має ID вимоги. Якби рядок його не мав — це сигнал, що або тест зайвий, або вимогу забули записати в `rtm.md`.
