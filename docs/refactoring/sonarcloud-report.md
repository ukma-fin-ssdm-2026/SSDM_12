Борг за S3776 — як у SonarQube: 5 хв на функцію понад поріг 15 і ще по 1 хв за кожен пункт
понад нього.

| Сигнал | До (`v0.1.0`) | Після (`v0.1.1`) |

| Найбільша складність функції | 146 (`check_architecture.main`) | 44 (`load_midterm.run`) |
| Сумарна когнітивна складність | 1398 | 1381 |
| Дублювання ≥ 100 токенів (`jscpd`, Python і JS) | 0 | 0 |

**Сумарна складність майже не змінилася — і це очікувано.** Рефакторинг не прибирає логіку,
а розкладає її на іменовані частини: перевірок у `check_architecture.py` стільки ж, скільки
було. Знижується пікова складність, яку читає людина й штрафує S3776, — тому борг упав на
57%, а сума — на 1%.

Команда, щоб відтворити:

```bash
python -m pip install complexipy==8.3.0
complexipy src scripts --plain --sort desc --top 15
```

### 5.1. R-1 · `scripts/check_architecture.py` — @NykytaBabakov

- **Де:** `scripts/check_architecture.py`, функція `main` (Лаб 3, крок CI «Check architecture
  artifacts and diagram syntax»). Тестів на модуль до Лаб 8 не було.
- **Запах:** Long Method — 260 рядків, 12 перевірок підряд, когнітивна складність 146,
  цикломатична 104 (`radon`, ранг F); вкладена функція `report` змінює лічильник через
  `nonlocal`, тож стан перевірки розмазано по всьому `main`.
- **Техніка:** Replace Function with Command — `report` стала класом `Report`, який друкує
  результат і рахує порушення; Remove Parameter — параметр `fmt` жоден виклик не передавав;
  Extract Method ×20 — кожна перевірка повертає список порушень, а друк лишився в `main`.
- **Що лишилося незмінним:** текст виводу байт у байт, порядок перевірок і рядків, код виходу
  (0, 1, а за відсутності файлів вимог — 2 з `check_requirements.load`), ранній вихід без
  основних документів, команда `java -jar … --check-syntax` з тими самими аргументами.
- **Що змінилося в структурі:** `main` — лише порядок кроків і підсумок (складність 5); кожна
  перевірка — функція з назвою й докстрінгом, яку можна викликати й тестувати окремо;
  регулярні вирази `ID_PATTERN`, `FENCE`, `SLOT` — константи модуля.
- **Який тест це доводить:** `tests/unit/test_check_architecture.py` — 16 характеризаційних
  тестів, закомічених **до** рефакторингу (бонус 2): повний текст виводу й код виходу на
  синтетичному репозиторії, по сценарію на кожну перевірку, гілкове покриття модуля 99%.
  Плюс звірка на справжньому репозиторії — вивід до й після однаковий:

  ```bash
  python scripts/check_architecture.py --plantuml plantuml.jar --strict > after.txt
  git stash && python scripts/check_architecture.py --plantuml plantuml.jar --strict > before.txt && git stash pop
  diff before.txt after.txt   # порожньо
  ```

- **Виміряно:** когнітивна складність `main` 146 → 5, найбільша у файлі — 15
  (`matrix_rows`, на порозі S3776, не понад нього); цикломатична `main` 104 → 6. Рядків у файлі
  374 → 479: докстрінги й сигнатури нових функцій — ціна читабельності.
- **Агент:** рефакторинг згенерував агент (Claude) за завданням із §8; я прочитав діф
  рядок за рядком, ‹що саме перевірив і що змінив сам›.
