## D-01 — реальна помилка структури курсора (дефект, знайдений у роботі)

**Симптом.** GET `/api/v1/slots` із base64url JSON
`{"s":"2026-10-20T09:00:00Z","i":7}` піднімав `AttributeError` замість
контрактного 422. У TestClient виняток поширюється в тест; у серверному обробнику
це непередбачена помилка 500. Некоректні дані не мають ставати серверною помилкою.

**Причина.** JSON розбирався успішно, але типи полів не перевірялися.
`uuid.UUID(7)` викликає метод рядка, якого число не має; AttributeError
не входить до переліку очікуваних помилок декодера.

**Відтворення.** Під час цього прогону до ізольованої копії актуальних тестів підставлено точний
`src/api/pagination.py` із історичного main `79f21d7`, без редагування робочого дерева.
`tests/api/test_lab06_regressions.py`: 1 failed; після поточного виправлення — 1 passed.
[До](lab06/evidence/cursor-before.txt) · [Після](lab06/evidence/cursor-after.txt).

**Виправлення.** Функція `cursor_fields` у [pagination.py](../../src/api/pagination.py) перевіряє, що JSON — об'єкт,
а `s` та `i` — рядки. `decode_cursor` перекладає TypeError у ApiProblem
`VALIDATION_FAILED`, поле `query.cursor`, 422. Розбір дати й UUID виконується
після перевірки структури. Зовнішній OpenAPI-контракт не змінено.

**Регресії.** [Модульні тести курсора](../../tests/unit/test_cursor_validation.py),
[API-регресія](../../tests/api/test_lab06_regressions.py), генеративний
[тест неправильних типів id](../../tests/property/test_cursor_shapes.py) (100 прикладів).

**Урок.** Синтаксично правильний JSON ще не є правильною структурою даних;
розбирати очікувані типи слід до виклику низькорівневого парсера.

## D-02 — навмисна помилка межі скасування

**Зміна для вправи.** У тимчасовій копії [доменних правил](../../src/unislot/booking/domain/rules.py)
умову `now > deadline` навмисно замінено на `now >= deadline`.
За FR-041 рівно в дедлайн скасування дозволено. Помилка давала відмову,
хоча `can_cancel` у відповіді ще дозволяв дію.

**RED.** Два [unit-тести сервісу](../../tests/unit/test_booking_service.py):
`test_cancel_exact_deadline_allowed` і
`test_can_cancel_view_agrees_with_command_at_exact_deadline` — **2 failed**.

**GREEN.** Повернення `>` у тимчасовій копії — **2 passed**.
Основний домен з Лаб5 не редагувався: SHA-256 до/після однаковий.

Команда `python scripts/debug_lab06.py` повторює вправу без поломки робочої копії.
[Патч](debug-challenge/lab06-deadline.patch) · [RED](lab06/evidence/debug-red.txt) ·
[GREEN](lab06/evidence/debug-green.txt) · [Результат](lab06/evidence/debug-results.json).

**Регресія й урок.** Порівняння `>`/`>=` — частина контракту; тестувати треба
рівно межу та ±1 мкс. Команда скасування й ознака доступності дії мають узгоджуватися.
Це реальна локальна вправа з навмисною помилкою, не студентська історія TDD.

## Автоматизоване трасування межі скасування у Windows CI (03.11.2026)

У PR #263 додано `tests/unit/test_lab06_deadline_trace.py`. Тест використовує
`sys.settrace` для фіксації фактичного проходження рядка 128
(`if now > deadline:` у `ensure_changeable`) без ручного breakpoint у VS Code.
Це **автоматизоване трасування**, а не запис особистої сесії Дениса в IDE.

Успішний запуск [GitHub Actions #41542344865](https://github.com/ukma-fin-ssdm-2026/SSDM_12/actions/runs/41542344865)
на Windows runner (коміт `273b777e`). У завантаженому артефакті
`api-coverage` файл `docs/testing/lab06/junit.xml` містить property
`lab06_automated_deadline_trace` для тесту `test_exact_deadline_trace`:

- рядок виконання: **128**, один виклик;
- `now = 2026-10-21T05:00:00+00:00`;
- `deadline = 2026-10-21T05:00:00+00:00`;
- `now == deadline` — **true**;
- стек: `ensure_changeable` → `_check_changeable` → `cancel` →
  `test_exact_deadline_trace`.

У цій ситуації `now > deadline` — **false**, тому скасування у точний
граничний момент дозволено. Фактичний звіт CI: **761 passed**,
сукупне покриття **98,28%** (поріг 90%). Експеримент із
`>` → `>=` описано окремо в D-02; він виконувався автоматизованим

## Особиста демонстрація налагодження

**Фактична сесія:** 03.11.2026, Денис Пацеля, Visual Studio Code на Windows
(версію редактора на скриншотах не зафіксовано). Запущено конфігурацію
`Lab 6: Cancellation deadline (pytest)` для тесту
`tests/unit/test_booking_service.py::test_cancel_exact_deadline_allowed`.

**Зупинка у відлагоджувачі.** Оскільки встановлення звичайного breakpoint
через інтерфейс не спрацювало, у локальній робочій копії перед умовою
`if now > deadline:` тимчасово вставлено `debugpy.breakpoint()` за допомогою
`Lab06-Force-Pause.ps1`. Це **особиста інтерактивна сесія у VS Code**,
а не трасування `sys.settrace` в CI. Точка зупинки була у
`ensure_changeable` на початковому рядку 128; після вставки двох тимчасових
рядків умова змістилася до рядка 130. Знімок екрана VS Code відображає
призупинений процес із панелями **Variables** та **Call Stack**.

**Значення з панелі Locals під час зупинки:**

- `now = datetime.datetime(2026, 10, 21, 5, 0, tzinfo=datetime.timezone.utc)`;
- `deadline = datetime.datetime(2026, 10, 21, 5, 0, tzinfo=datetime.timezone.utc)`;
- `slot.starts_at = datetime.datetime(2026, 10, 21, 7, 0, tzinfo=datetime.timezone.utc)`;
- `status = BookingStatus.CONFIRMED`.

Отже, `now == deadline` — **True**, `now > deadline` — **False**.
Сусідня перевірка `now >= slot.starts_at` теж має значення **False**:
05:00 UTC раніше за 07:00 UTC. Тому ані `SlotStarted`, ані
`CancellationDeadlinePassed` не мають виникати. Умова з `>`
узгоджується з FR-041: скасування рівно в дедлайн дозволене, а
`>=` для початку слота блокує дію вже на момент початку слота.

**Зафіксований стек:** `ensure_changeable` ← `_check_changeable` ←
`cancel` ← `test_cancel_exact_deadline_allowed`. Наступний знімок
екрана показує повернення до `_check_changeable` у
`src/api/stubs/booking_service.py:179` і відсутність активної
Debug-сесії у VS Code. Окремий підсумок саме цього Debug-запуску
(`1 passed`) на цих знімках **не зафіксовано**.

**Контрольний тест до інтерактивної сесії:** у виводі PowerShell після
підготовки конфігурації показано `1 passed in 0.51s`.
Це окремий звичайний запуск pytest, не результат Debug-запуску.

**Співвідношення з попередніми доказами.** Спостереження в IDE
збігаються з автоматизованим трасуванням Windows CI вище; D-02 вже
документує експеримент `>` → `>=` та RED/GREEN і не повторюється.
Інтерактивна демонстрація підтверджує використання інструментів VS Code
для огляду змінних і стека, але не підміняє автоматизовані докази.

**Відновлення оригінального коду та повторна перевірка.** Після завершення
інтерактивної сесії Денис у Windows PowerShell виконав
`Lab06-Force-Pause.ps1 -Undo` та отримав повідомлення
`Temporary breakpoint removed from rules.py.`. Команда
`git status --short -- src/unislot/booking/domain/rules.py` не вивела
жодного рядка — робочий `rules.py` чистий. Повторно запущено
`python -m pytest tests/unit/test_booking_service.py::test_cancel_exact_deadline_allowed -q --no-cov`
через `.venv`: **1 passed in 0.26s**. Це контрольний тест **після**
очищення тимчасових змін, а не результат Debug-запуску.
