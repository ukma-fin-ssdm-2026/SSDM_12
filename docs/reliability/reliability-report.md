## Виправлення та відновлення

### R-01. Конфігурація

До, `src/api/config.py`:

```python
session_ttl_seconds=int(os.environ.get("UNISLOT_SESSION_TTL_SECONDS", "28800")),
```

Після:

```python
session_ttl_seconds=_bounded_int("UNISLOT_SESSION_TTL_SECONDS"),
```

`_bounded_int()` повертає документоване типове значення для порожнього поля
(безпечна відмова). Для нечислового чи позамежного вводу запуск зупиняється з
назвою змінної (швидка відмова). Оператор бачить причину в журналі запуску,
виправляє змінну та перезапускає процес. Не підставляємо тихо іншу межу безпеки.
Доказ: [граничні тести](../../tests/reliability/test_config_env_validation.py), QA-15.

### R-02. Діагностика відмови доставки

До, `src/api/infrastructure/outbox.py`:

```python
except (DeliveryUnavailable, TimeoutError, OSError):
    repository.finish(notice, now, policy, error=True)
```

Після, скорочений фрагмент:

```python
except (DeliveryUnavailable, TimeoutError, OSError) as exc:
    code, cause = failure_code(exc), exc.__cause__
    # Структурований warning з кодом і назвами класів помилок.
    repository.finish(notice, now, policy, error=True, reason=code)
```

Безпечна відмова доставки. Бронювання вже збережене, а тимчасовий збій адаптера
залишає сповіщення у черзі. Оператор бачить короткий код і клас винятку без тіла
сповіщення чи сирого тексту драйвера. Worker повторює доставку за розкладом до
ліміту, після чого запис стає `failed` і доступний для контрольованого повтору.
Докази: [тести діагностики](../../tests/reliability/test_dispatch_diagnostics.py) та
[інтеграційний сценарій черги](../../tests/integration/test_outbox.py), REL-002.

### R-05. Явна відмова транзакції

До, `src/api/infrastructure/unit_of_work.py`: після циклу `for attempt in range(...)`
функція не мала завершального `raise`. Після:

```python
raise ApiProblem(
    ErrorCode.TRANSIENT_CONFLICT, headers={"Retry-After": "1"}
)
```

Швидка контрольована відмова. Якщо майбутня зміна циклу зробить цей шлях досяжним,
клієнт отримає 503 із `Retry-After`, замість того щоб отримати неявний результат
`None`. Запобіжник латентний: сьогодні всі гілки циклу повертають результат або
піднімають виняток. Доказ — [код і обґрунтування в §4.3](scavenger-hunt.md#43-r-05--guard-clause).

### R-07. Відступ Worker

До, `scripts/run_worker.py`:

```python
time.sleep(args.interval)
```

Після, обчислення наступної паузи:

```python
return min(previous * 2, interval * MAX_BACKOFF_FACTOR)
```

Безпечна деградація для операційного збою всередині циклу. Worker реєструє
помилку і відкладає наступну спробу. Після успішного циклу пауза скидається до
`--interval`. У режимі `--once` збій дає ненульовий код завершення. Межа паузи —
60 × `--interval`. Запуск і створення підключення до входу в цикл не покриваються
цим відступом. Доказ: [тести відступу](../../tests/reliability/test_worker_backoff.py).

### R-08. Запуск API при відмові запису

До, `src/api/main.py`: `openapi_export.write_artifacts(app)` виконувався в lifespan
без перехоплення помилки запису. Після, скорочений фрагмент:

```python
try:
    for path in openapi_export.write_artifacts(app):
        logger.info("OpenAPI згенеровано з коду → %s", path)
except OSError as exc:
    logger.warning(
        "OpenAPI не записано (%s); чинною лишається специфікація з репозиторію",
        type(exc).__name__,
    )
```

Безпечна деградація допоміжного експорту. При `PermissionError` чи read-only FS
API піднімається, `/health` відповідає 200, а в журналі є warning. Оператор
відновлює доступ до каталогу й запускає експорт знову. Дефект генерації
(`RuntimeError`) зупиняє запуск, щоб помилкова специфікація не залишилася непоміченою.
Доказ: [тести з ін'єкцією збою](../../tests/reliability/test_startup_degradation.py), QA-16.

## Бонуси

### 1. Повтори з повним jitter — Денис Пацеля

Команда [`scripts/check_readiness.py`](../../scripts/check_readiness.py) виконує
ідемпотентний `SELECT 1` із лімітом 1 с на підключення та запит у межах спроби.
Після тимчасового збою є максимум дві повторні спроби. Пауза випадкова в межах
0–100 мс перед другою та 0–200 мс перед третьою спробою. Після третьої
невдачі команда завершується з JSON-станом `unhealthy` і кодом 1.
У [тестах](../../tests/reliability/test_postgres_readiness.py) перевірено відновлення
на другій спробі, скасування завислого виклику після тайм-ауту, ліміт трьох спроб
і відсутність паузи після останньої.

### 2. Перевірка готовності PostgreSQL — Денис Пацеля

Команда читає `UNISLOT_DATABASE_URL` із середовища або із вказаного файлу
конфігурації проєкту. `healthy` і код 0 означають, що PostgreSQL прийняв з'єднання
і виконав запит. Збої дають `unhealthy` і код 1. Відсутній або непридатний URL
дає `misconfigured` і код 2. У результаті є лише стан, назва залежності
та, якщо був виклик, кількість спроб. Тести ін'єктують відмову драйвера та зависання.
Залишок ризику R-04 описано в розділі «Відкриті й частково вирішені ризики».

```text
PostgreSQL 16 в ізольованому кластері → {"status": "healthy", "dependency": "postgresql", "attempts": 1}  (exit 0)
Локальний TCP-сервер приймає з'єднання й не відповідає → {"status": "unhealthy", "dependency": "postgresql", "attempts": 3}  (exit 1)
```

```bash
python -m pytest -q tests/reliability/test_postgres_readiness.py
python -m scripts.check_readiness --env-file .env.local
```

Вкажіть свій файл середовища проєкту. Якщо `UNISLOT_DATABASE_URL` уже налаштовано,
аргумент `--env-file` можна опустити. Демо зі збоєм запускайте на ізольованій БД
або тестовому дублері.
