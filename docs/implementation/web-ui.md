# Кабінети UniSlot — локальний етап

**Дата:** 31.10.2026. **Гілка:** feature/midterm-admin-availability.
Продовження [Auth](password-auth.md) і [PostgreSQL/outbox](postgres-outbox.md)
на базі main `7e384d251c3c267d340a6f2e9aece704241a56a7`.
Зміни локальні; push, PR і новий GitHub CI не виконувалися. Лаб8 не змінювалася.
Цей звіт фіксує перший UI-етап. Наступні календар, читання аудиту, Worker та
SQL-оптимізації описані [окремо](load-worker-calendar-audit.md); числа нижче історичні.

## Реалізовані сценарії

| Кабінет | Що можна виконати |
|---|---|
| Вхід | Реєстрація студента, повтор пароля, вхід, відновлення cookie-сесії після reload, вихід; помилки полів, 401/403/409/422/429/503 із request_id |
| Студент | Пошук за типом, провайдером, київською датою й місткістю; наступна сторінка курсором; бронювання з Idempotency-Key; свої записи зі станом і дедлайном; перенесення й підтверджена відміна |
| Провайдер | Власні ресурси й опубліковані слоти зі станом доступності; створення разового слота; створення та редагування тижневого шаблону з конфліктами; блокування часу з причиною та зняття блокування |
| Адміністратор | Створення/редагування ресурсу, місткість аудиторії, призначення провайдера; пошук користувачів, надання/відкликання ролей; читання й зміна політики бронювання |
| Сповіщення | Особиста постійна скринька, доставлені Worker підтвердження, нагадування й причини скасувань; оновлення та пагінація |

Студент бачить право зміни за серверним can_cancel, а не за незалежною копією
правила в JavaScript. Під час перенесення старе бронювання чинне до успіху операції.
Зняття блокування не відновлює скасовані записи. Оновлення політики змінює дедлайн
нових бронювань, а знімок політики попередніх зберігається.

## Код і додані контракти

Оболонка й CSS/SVG — src/api/web/, ESM-клієнт — client.mjs, екрани — app.mjs.
GET `/` повертає оболонку; `/static/` віддає її ресурси. Збірки та npm-залежностей
немає. Node.js 22+ потрібен тільки для автоматичних тестів клієнта; браузер і API
не запускають Node. На Windows MIME .mjs явно задано як text/javascript: системний
реєстр інакше може віддавати text/plain та блокувати запуск модулів.

Для екранів додано чотири операції читання у routers/workspace.py:

- GET `/api/v1/admin/users` — q/role/limit/offset, тільки адміністратор;
  хеші паролів, сесії та лічильники входу не серіалізуються.
- GET `/api/v1/resources/{resource_id}/slots` — власні активні слоти, що ще
  не закінчилися, зі станами available/booked/blocked/started/outside_horizon.
- GET `/api/v1/resources/{resource_id}/templates` — власні шаблони з конфліктами.
- GET `/api/v1/resources/{resource_id}/blocks` — власні збережені блокування.

Три останні списки доступні лише провайдеру-власнику, не містять адрес та ID
студентів. Перевірка власника виконується під транзакційним lock; роль перечитується
з БД. Пагінація offset узгоджена з рештою каталогів. Загалом **30 операцій API**;
OpenAPI й каталог помилок повторно згенеровані з коду.

Ці списки не підміняють повний календар із даними бронювань FR-015 чи перегляд
аудиту FR-068. Наявність відповідного екрана не означає завершення всіх FR модуля.

## Безпека й час

API та UI мають один origin; session — HttpOnly cookie, CSRF — прив'язаний до
сесії заголовок X-CSRF-Token. Після reload клієнт бере його з unislot_csrf cookie.
Токени не записуються в localStorage/sessionStorage. Усі дані користувачів
додаються як текстові DOM-вузли; innerHTML не використовується. Оболонка має CSP
без inline-скриптів/стилів і зовнішніх CDN, no-store, nosniff, frame-ancestors none.
Приховування пункту меню не є механізмом авторизації: права перевіряє API.

Усі відображення часу — Europe/Kyiv. Ввід місцевого часу перетворюється в UTC;
весняна прогалина й осіння неоднозначна година відхиляються з поясненням.
Межі полів беруться з Code-First схем; пароль рахується в Unicode code points,
як Python, без trim. Старі асинхронні відповіді не замінюють новішу сторінку.
Невизначений результат POST бронювання зберігає ключ для безпечного повтору.

## Нативний локальний запуск

Команди PowerShell виконувати з кореня власного репозиторію. Python 3.12+,
PostgreSQL 16 binaries; Node.js 22+ для тестів. Якщо .venv ще немає:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Підготувати/підняти окрему локальну БД, зберігши наявні дані:

```powershell
.\.venv\Scripts\python.exe scripts/manage_db.py local-init
.\.venv\Scripts\python.exe scripts/manage_db.py migrate --env-file .env.migrations.local
```

Першого адміністратора створюють один раз зі своїми адресою та паролем
за [інструкцією Auth](password-auth.md#запуск-і-перший-адміністратор).
Далі API в першому терміналі:

```powershell
.\.venv\Scripts\python.exe -m uvicorn api.main:app --app-dir src --env-file .env.local --port 3000
```

Worker в другому терміналі:

```powershell
.\.venv\Scripts\python.exe scripts/run_worker.py --env-file .env.local
```

Відкрити **http://127.0.0.1:3000/**. Студенти реєструються через UI; адміністратор
призначає провайдерів і ресурси. Парольних демо-акаунтів у продукті немає.
Для реальних сесій використовувати UNISLOT_DEMO_AUTH=0. local-init явно задає
Secure=0 лише для loopback HTTP; для HTTPS стандартне значення Secure=1.
Ігноровані .env.local/.env.migrations.local не завантажують у GitHub чи архів здачі.

Після роботи зупинити API/Worker Ctrl+C, потім `scripts/manage_db.py stop-local`.

## Перевірка

Автоматичні перевірки клієнта запускаються також із повного pytest-прогону:

```powershell
node --test tests/web/client.test.mjs
.\.venv\Scripts\python.exe -m pytest -q tests/api/test_workspace.py tests/unit/test_web_client.py
.\.venv\Scripts\python.exe -m pytest -q --cov=api --cov=unislot --cov-branch --cov-fail-under=90
```

API-тести перевіряють списки, пагінацію, форму відповідей без секретів,
доступ власника/чужого провайдера/студента/адміністратора/анонімного користувача,
статичну оболонку й MIME модулів. Дев'ять Node-тестів перевіряють UTC/DST,
CSRF, cookie, Idempotency-Key, помилки мережі/429/503 й offset-пагінацію.
Це тести HTTP-клієнта й перетворень, а не заміна браузерного огляду DOM.

Браузерний огляд виконано на окремому тимчасовому PostgreSQL-кластері й окремому
Worker, із синтетичними акаунтами, demoBearer=0 та реальними cookie-сесіями:

1. Реєстрація: відхилено різні повтори пароля, правильний запис створено; вхід/вихід
   та reload зберегли очікуваний стан сесії.
2. Студент: пошук за провайдером/датою; бронювання 10:00, повідомлення від Worker;
   перенесення на 11:00 з історією старого запису; скасування з поверненням слота.
3. Провайдер: створено разовий слот 13:00; шаблон понеділка 14:00–16:00 змінено
   на 14:00–17:00; опубліковано шість слотів. Блок 12:00–12:30 скасував одне
   бронювання з причиною; блок знято, запис лишився скасованим.
4. Адміністратор: знайдено студента за адресою, надано й відкликано роль provider;
   створено аудиторію на 18 осіб і змінено на 24; призначено провайдера.
   Політику змінено з вікна 120 на 90 хв: новий запис 13:00 має дедлайн 11:30,
   попередні записи зберегли свої дедлайни.
5. Студент отримав у скриньці причину блокування; нові слоти шаблону знайдено
   через пошук. На 1280×900 перевірено кабінет; на 390×844 — картки й діалог:
   ширина документа дорівнювала viewport, діалог умістився. Console warn/error — 0.

Артефакти перевірки: Midterm_features_2026-10-31/web-ui поза репозиторієм;
student-search.png, mobile-bookings.png, worker.txt, журнали воріт і покриття.
Повний фінальний локальний прогін: **612 passed**, 82,71 с; api + unislot,
рядки й гілки — **98,50%**, поріг 90% збережено. Це серверне покриття; відсоток
покриття DOM/JavaScript ним не вимірюється. Усі 13 воріт завершилися кодом 0:
pytest, Ruff, формат, Bandit, вимоги, простежуваність, strict-архітектура/PlantUML,
import-linter, OpenAPI, pip check, pip-audit, whitespace, detect-secrets.
Перевірено Windows 10, Python 3.13.13, Node.js 22.22.2, PostgreSQL 16.
Це локальні результати; майбутній CI потребує Node.js і PostgreSQL binaries
на своєму runner. Історичні звіти Лаб6 не перегенеровано цим прогоном.

## Відкриті межі

- FR-015/FR-068 і питання їх включення в обсяг OQ-004 лишаються відкритими;
  окремо не закриті OQ-001 та строки зберігання даних AQ-06.
- PORT-001 (відтворюваний нативний запуск), цільові навантаження PERF-001/002, масштабований
  repository layer, автоматичний розклад розширення горизонту й ручний retry
  вичерпаних повідомлень не завершені цим UI-етапом.
- UX має responsive-верстку, підписи, клавіатурні форми й повідомлення стану,
  але формальний аудит доступності та повна матриця браузерів не виконувалися.
- Кабінет перевірений на локальній гілці; висновок викладача про відсоток готовності
  потребує окремого перегляду main після майбутнього командного злиття.
