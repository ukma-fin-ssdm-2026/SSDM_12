я перевірила тестами й аналізом коду:

|---|---|---|

## 8. Аналіз у робочому процесі

1. **На машині розробника — pre-commit** (`.pre-commit-config.yaml`): Ruff із `--fix`, форматер,
   Bandit, detect-secrets і базові перевірки файлів до кожного коміту.
2. **На кожен pull request — CI**, job `build`: ті самі інструменти плюс pip-audit і
   import-linter, до тестів (статичні кроки тривають секунди й зупиняють зламану зміну рано).
   Це важливо, бо частина команди комітить у вебредакторі GitHub, де хуки не працюють.
3. **Щотижня — Dependabot** (`.github/dependabot.yml`): PR з оновленнями пакетів pip і дій
   GitHub Actions проходять той самий огляд і CI.
4. **Що робити зі знахідкою** — статут §11.5: виправити; придушити точково з коментарем «чому»
   (`# nosec B310`, `# noqa: S310`); відкалібрувати правило в конфігурації із записом у цей
   документ. Придушення переглядає Керівник якості щолабораторну.
