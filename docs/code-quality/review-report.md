# Code review: `src/api/`

**Репозиторій:** [`ukma-fin-ssdm-2026/Monkey-Business-project`](https://github.com/ukma-fin-ssdm-2026/Monkey-Business-project)
**Комміт:** `73d7d4f` · **Дата:** 2026-10-05 · **Обсяг:** ~770 рядків Python у 6 модулях

Перевірено читанням коду + один прогін `ruff` і `pylint`.

---

## Сильні сторони

**1. Обробка помилок винесена в одне місце.** `errors.py` задає єдиний формат відповіді (код, повідомлення, деталі по полях, `request_id`, посилання на docs) і реєструє два обробники через `register_error_handlers(app)`. Роутери кидають `NotFoundError` і більше нічого про HTTP не знають — типового розповзання форматів помилок по ендпоінтах тут немає. Хелпер `error_responses()` ще й має коментар, який пояснює, навіщо він потрібен: без явного 422 FastAPI документує свій дефолтний `HTTPValidationError`, а не те, що насправді повертається.

**2. Докстрінги пояснюють рішення, а не переказують код.** `routers/cards.py` обґрунтовує, чому `move` — це `POST .../move`, а не `PATCH`. `schemas.py:157` пояснює, чому поле зветься `position_index`, а не `position` (бо `position` — назва посади). Останнє особливо корисне: воно запобігає саме тій помилці, яку наступний розробник зробив би за замовчуванням. Трасування на FR-коди наскрізне — від модуля до опису кожного поля.

**3. Code-First працює насправді.** Специфікація генерується з коду, CI відтворює ту саму команду, закоммічений YAML збігається з тим, що віддає застосунок. `mcp_server.py` на 23 рядки перетворює API на MCP-сервер через `FastMCP.from_fastapi` — нові ендпоінти стають інструментами самі, без другого джерела правди.

## Що варто виправити

**1. `PATCH` не може очистити поле.** `store.py:81`:

```python
record.update({k: v for k, v in changes.items() if v is not None})
```

Роутер коректно відрізняє «не надіслали» від «надіслали null» через `exclude_unset=True`, але `store` цю різницю одразу відкидає. Прибрати дедлайн (FR-010), очистити `requirements_text` чи `vacancy_url` неможливо — явний `null` просто ігнорується. Баг непослідовний: `{"notifications_enabled": false}` працює, бо `False is not None`, тож ручним тестуванням його легко не помітити.

Фільтр треба прибрати — роутер і так передає лише явно надіслані поля:

```python
record.update(changes)
```

**2. Немає ні конфігу лінтера, ні перевірки якості в CI.** У репозиторії відсутні `pyproject.toml`, `.ruff.toml`, `.pylintrc` — будь-які. CI виконує тільки генерацію специфікації: ні лінтера, ні тестів.

Через це `ruff` видає ~40 зауважень, з яких близько половини (`B008` на `Path(...)` / `Query(...)`) — хибні, бо це документована ідіома FastAPI. `pylint` ставить 5.90/10, переважно за відсутні докстрінги функцій і довгі рядки.

Правильний шлях — не придушувати `B008`, а перейти на сучасну форму `Annotated`, яка знімає і `B008`, і `UP045` по суті:

```python
board_id: Annotated[UUID, Path(description="Ідентифікатор дошки")]
stage_id: Annotated[UUID | None, Query(description="Фільтр за етапом")] = None
```

Після цього додати `pyproject.toml` з `select`/`line-length` і крок `ruff check src/` у CI. Окремо варто перевіряти дрейф специфікації — зараз CI переконується лише, що файл не порожній, тож застарілий YAML пройде перевірку. Достатньо `git diff --exit-code docs/api/openapi-generated.yaml`.

**3. Дублювання, яке згодом обійдеться дорого.** `_require_card` існує дослівно однаковим у `routers/cards.py:58` і `routers/card_links.py:24`. Саме сюди згодом ляже перевірка прав власності — і внести її доведеться у два місця. Паралельно `_to_card_out` вручну перелічує 13 полів, хоча `CardOut` має `from_attributes = True`.

Обидва випадки лікуються однаково — винести перевірки у FastAPI-залежності:

```python
def require_card(board_id: Annotated[UUID, Depends(require_board)], card_id: UUID) -> dict: ...
```

Роутер тоді зводиться до `CardOut.model_validate(record)`, а `_to_card_out` зникає. Побічно це виправляє й неузгодженість: у `card_links.py` перевірка існування дошки зараз пропущена, тому запит до неіснуючої дошки повертає «Картку не знайдено».

## Потенційна вразливість

**Тіло запиту повертається клієнтові у відповіді 422** — `errors.py:86`, CWE-209.

```python
provided_value=str(err.get("input")) if err.get("input") is not None else None,
```

Для помилки рівня поля це лише значення поля — нормально. Але коли **обов'язкове поле відсутнє**, Pydantic кладе в `err["input"]` усе тіло запиту, і воно повертається клієнтові цілком, окремо для кожного відсутнього поля. Обмеження `max_length` зі схем тут не діють — вони застосовуються вже після парсингу.

Зараз, поки в API немає автентифікації, ціна невелика. Але `data-model.md` позначає `users.password_hash` і `board_mentors.invite_token` як чутливі: щойно з'явиться `POST /auth/login`, одне пропущене поле в тілі — і пароль повертається у відповіді, а тіла 4xx осідають у логах nginx, проксі та системах моніторингу. Це прямо підсилює ризик **R1** з нашої ж моделі загроз.

Виправлення — не віддавати `input` для помилок типу `missing` і для словників, обрізати довжину, ховати чутливі ключі:

```python
if err["type"] == "missing" or isinstance(value, (dict, list)):
    return None
return str(value)[:200]
```

Повідомлення «Field required» і так повністю пояснює клієнтові проблему.
