## 1. Поточний результат

Реалізовано REST API із 14 операціями, каркас восьми модулів `src/unislot/`
і перший робочий компонент за архітектурою — доменний шар `Booking`.
Правила бронювання винесено з API-заглушки в чисті функції; REST API перетворює
`DomainError` у відповідь `application/problem+json`.

Прототип працює з даними в пам'яті. Постійного сховища PostgreSQL, користувацького
Web UI, сесійної автентифікації та фонової доставки сповіщень ще немає.
Пакети інших модулів містять опис відповідальності; наявність пакета не означає,
що весь модуль уже реалізовано.

## 3. Перший робочий компонент — Booking

[PR #163](https://github.com/ukma-fin-ssdm-2026/SSDM_12/pull/163) переніс правила
з `api.stubs.booking_service` у `unislot.booking.domain`:

| Частина | Реалізована поведінка |
|---|---|
| `model.py` | Стани бронювання, незмінні `Interval` і `BookingPolicy`; напіввідкриті інтервали та відхилення порожнього/перевернутого інтервалу |
| `derive_state` | Похідний стан залежно від статусу та моментів початку/кінця слота |
| `cancel_deadline`, `can_cancel` | Граничний час скасування та доступність дії на межі включно |
| `ensure_slot_bookable` | Слот ще не почався, лежить у горизонті, не заблокований і не зайнятий; порядок відмов збережено |
| `ensure_within_student_limits` | Ліміт активних бронювань і відсутність перетинів; перенесення не додає ще одне бронювання до ліміту |
| `ensure_changeable` | Зміна лише чинного бронювання, до початку слота й до граничного часу включно |
| `errors.py` | Причини відмов як доменні помилки без HTTP-статусів; REST API бере опис і статус із каталогу DD-07 |

Домен імпортує стандартну бібліотеку й власні модулі, без FastAPI, Pydantic,
SQLAlchemy та API-сховища. Горизонт передається параметром. Заглушка збирає
вхідні дані й змінює сховище під `store.lock`; майбутній адаптер БД має
замінити цю частину без перенесення HTTP у домен.

У CI файл `tests/unit/test_booking_rules.py` виконує **32 тестові випадки**.
Самі перевірки правил обходяться без HTTP-викликів. Весь pytest-процес усе ще
використовує спільний `tests/conftest.py`, а один тест звіряє коди помилок
із каталогом API; це не твердження про повну незалежність усієї тестової збірки від FastAPI.

|---|---|---|

версії звірено з повідомленнями супроводжувачів.

Це технічні наступні кроки, а не нове призначення ролей Лаб6 або заява про вже виконану роботу.

## 6. Відомі обмеження

- Перезапуск процесу скидає дані; сховище й журнал аудиту існують тільки в пам'яті.
- Блокування `RLock` захищає один процес. Гарантії інваріантів між процесами
  та транзакціями PostgreSQL для робочого API ще не доведено.
- Демо-токени не замінюють сесії й паролі; тепер вони вимкнені за замовчуванням,
  а явний демо-режим залишається тимчасовим рішенням DD-18.
- Роутери й заглушки ще виконують частину ролі application; повного набору
  інтерфейсів і адаптерів HLD §5.2 немає.
- Числа CI підтверджують тестовий прототип, а не готовність усіх вимог,
  продуктивність із БД чи завершеність користувацької системи.
