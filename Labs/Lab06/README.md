## Відтворення

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade "pip>=26.2"
.\.venv\Scripts\python.exe -m pip install -r requirements-testing.txt
.\.venv\Scripts\python.exe scripts/run_lab06.py
.\.venv\Scripts\python.exe scripts/debug_lab06.py
.\.venv\Scripts\python.exe scripts/check_lab06.py
```

Для необов'язкового mutation testing установити `requirements-mutation.txt`,
потім виконати `python scripts/mutation_lab06.py --label after`.
Звіт `before` — контрольний набір без доданих mutation-регресій, не особиста TDD-історія.
Вебредактор не запускає локальні хуки: треба доче­катися фактичного CI на останньому коміті.

## Особисті результати

Кожен сам виконує 6–12 малих комітів `[RED]`, `[GREEN]`, `[REFACTOR]`,
без squash, і записує **два окремі Loom-відео, кожне ≤5 хв**.
У `video_denys_patselia.txt`, `video_akseniia_kozulina.txt`,
`video_pavlo_dziubak.txt`, `video_nykyta_babakov.txt`:
перший рядок — URL TDD-відео; другий — URL відео про внесок. Створювати файли лише з реальними URL.
Підготовлені AI-матеріали не підтверджують особисті дії, відвідування чи огляд іншою людиною.

## Використання ШІ

Codex адаптував попередні локальні заготовки до поточного main, дописав код,
тести та документи, виконав локальні перевірки. Командна перевірка, студентські
TDD-коміти й відео подаються окремо за фактом виконання.

Окремо щодо TDD-циклу Никити (`src/api/log_paths.py`, `tests/unit/test_log_paths.py`,
`tests/api/test_access_log.py`): ціль, план, реалізацію й тести написав Claude (Opus 5);
Никита ухвалив план, виконав і перевірив кожен крок, закомітив кожен `[RED]` після
побаченого падіння й кожен `[GREEN]` після зеленого прогону, і є власником результату.
Повний опис, зокрема те, що у відео роль інструмента применшено, —
у `docs/testing/testing-strategy.md`, розділ «Використання ШІ».

## Розбіжності з відео

Відео записані раніше за ці нотатки й не перезаписувалися. Де вони розходяться
з репозиторієм, точним є репозиторій.

**Авторство.** TDD-відео викладає цикл від першої особи й інструмента не називає;
відео про внесок називає шість тестових випадків власною роботою. Обидва формулювання
применшують роль Claude — фактичний розподіл у розділі «Використання ШІ» вище
й у `docs/testing/testing-strategy.md`.

**Перебіг циклу 4.** У відео сказано, що перед цим циклом реалізація розпізнавала лише
малі літери і що тестів падає два. Насправді регістр виправлено раніше, у циклі 3
(`[RED]` `88e05a2` -> `[GREEN]` `ea49613`), і на `[RED]` циклу 4 (`a9e51c9`) падає
**один** тест — новий `test_thirty_six_character_non_identifier_is_preserved`.
Два падіння у відео — наслідок демонстрації, яка повертала реалізацію з `525c03d`,
на два цикли назад, залишаючи тести циклу 4; такого стану в історії не було.
Справжній `[RED]` циклу 4 відтворюється двома командами:

    git checkout a9e51c9 -- src/api/log_paths.py tests/unit/test_log_paths.py
    python -m pytest tests/unit/test_log_paths.py -q

**Тривалість циклів.** Орієнтир у 2-3 хвилини витримано в циклах 2, 3 і 4 — за мітками
комітів 36 с, 26 с і 48 с. Два цикли його перевищили: цикл 1 — близько 27 хвилин
(`0fb0308` 21:57 -> `e2d032d` 22:23), бо там налаштовувався запуск pytest; цикл 5 —
близько 10 хвилин (`0a66431` 22:32 -> `c63db2d` 22:42), бо це інтеграційний тест через
`caplog` і підключення до `middleware.py`. Історію не переписували: мітки перевіряються
